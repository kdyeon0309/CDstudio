# CDstudio 💿

YouTube/SoundCloud 음원으로 나만의 부틀렉 오디오 CD를 만드는 **개인 소장용 로컬 웹앱**.

음원 추출 → 트랙 편집 → AI 앨범 아트 생성 → 실치수 인쇄 → CD 굽기까지, 전 과정을 하나의 위저드로 제공한다. 모든 것이 내 컴퓨터 안에서만 동작한다 (localhost 전용, 서버·계정·DB 없음).

## ⚠️ 저작권 및 이용 고지

- 이 프로그램은 **사적 이용(사적 복제) 목적의 개인 소장용**으로만 사용해야 한다. 대한민국 저작권법 제30조는 영리 목적이 아닌 개인적 이용을 위한 복제를 제한적으로 허용하지만, **제작한 CD·추출 음원·앨범 아트를 판매, 배포, 공유, 업로드, 대여, 공연에 사용하는 것은 저작권 침해**다.
- 스트리밍 플랫폼의 음원 추출은 해당 플랫폼 이용약관(YouTube ToS 등)에 저촉될 수 있다. 그 판단과 책임은 전적으로 사용자 본인에게 있다.
- 이 저장소는 배포·공유 기능을 의도적으로 포함하지 않으며, 앞으로도 추가하지 않는다.
- 소프트웨어는 어떠한 보증 없이 "있는 그대로" 제공된다. CD-R 소모, 데이터 손실 등 사용 결과에 대한 책임은 사용자에게 있다.

## 요구 사항

- macOS (CD 굽기에 내장 `drutil` 사용) + USB 광학 드라이브(버너)
- Node.js 22+
- Python 3.10+, [ffmpeg](https://ffmpeg.org) — `brew install python ffmpeg`. yt-dlp는 아래 명령으로 이 앱에만 설치한다.
- ChatGPT 계정으로 로그인된 Codex CLI — 이미지 스튜디오에서 내장 이미지 도구로 표지를 생성한다. `codex login status`로 로그인 상태를 확인한다. 이미지 생성 기능을 지원하는 CLI/계정이 필요하며, 0.159.0에서 실제 PNG 생성·참고 이미지 변형을 검증했다.
- 기존 HTML 디자인은 Codex CLI를 기본으로 사용하며 Claude CLI 폴백도 지원한다.

## 실행

```bash
npm install
npm run setup:yt-dlp  # 공식 yt-dlp 2026.08.19을 .tools/에 내려받아 SHA256·버전 검증
npm run dev        # 개발 서버 → http://localhost:3000
```

브라우저에서 `localhost:3000` 접속 후:

1. **라이브러리** — 새 앨범 만들기, 기존 앨범 제목·아티스트 수정
2. **추출** — YouTube/SoundCloud URL 입력 → WAV 추출 (오디오 CD 규격 44.1kHz/16bit/스테레오 자동 변환)
3. **트랙 편집** — 순서 조정·삭제, 트랙 간격을 포함한 예상 디스크 점유 시간 표시. 굽기 전 실제 WAV와 CD 프레임 길이로 79분 상한 재검증
4. **디자인** — 앞표지·내부·라벨·뒷표지 중앙·접히는 스파인·뒷표지 내부의 6개 제작 영역별로 후보를 생성·변형·선택. 이전 HTML 3안은 기존 디자인 화면에서 유지
5. **인쇄** — 실치수(앞커버 120×120mm, 뒷커버 150×118mm, 라벨 Ø116mm) 인쇄/PDF 저장. A4·배율 100%로 인쇄할 것
6. **굽기** — 공 CD-R 또는 지울 수 있는 CD-RW를 감지하고 매체 용량·최신 트랙 목록을 확인한 뒤 `drutil`로 오디오 CD 굽기

앨범 데이터는 `~/CDstudio-library/`에 폴더별로 저장된다.

메타 조회와 음원 다운로드는 앱 전용 `.tools/yt-dlp` 2026.08.19를 함께 사용한다. 설치 파일이 없거나 검증에 실패하면 앱에서 재설치 명령을 안내한다. `npm run check:yt-dlp`로 설치 상태를 확인할 수 있다. Homebrew의 전역 yt-dlp는 이 앱이 사용하지 않는다. 이후 버전을 올릴 때는 `scripts/install-yt-dlp.mjs`의 버전·공식 릴리스 URL·SHA256과 `lib/audio.ts`의 SHA256을 함께 갱신해 검증한 뒤 `npm run setup:yt-dlp`를 다시 실행한다.

음원 다운로드에서 일시적인 HTTP 403이 발생하면 앱이 새 요청으로 최대 3회 시도하고, 추출 화면에 재연결 상태를 표시한다. 실패한 시도의 임시 파일은 정리하며 다른 트랙은 유지한다. 세 번 모두 거부되면 원본 링크 접근 상태와 yt-dlp 최신 지원 상태를 확인해야 한다. YouTube 측 변경에 따라 검증된 버전도 특정 영상의 추출을 보장하지는 않는다.

## 영역별 이미지 스튜디오

디자인 화면에서 앞표지·앞표지 내부·라벨·뒷표지 중앙·뒷표지 스파인·뒷표지 내부를 각각 작업한다. 뒷표지 스파인은 하나의 후보를 양쪽 6.5mm 접힘 영역에 반복 배치하며, 가운데 뒷표지는 137×118mm에 배치된다. 스파인을 선택하지 않으면 기존 150×118mm 뒷표지 출력 방식을 유지한다. 새 후보를 생성해도 현재 선택은 유지되며, 원하는 결과에 **이 후보 사용**을 눌러 적용한다. 후보별 생성 프롬프트와 참고 이미지, 변형 원본을 보존하고 현재 조합을 세트로 저장·복원할 수 있다.

AI 생성 없이 **내 이미지로 제작**에서 PNG·JPEG·WebP를 업로드하거나 기존 이미지를 골라 현재 영역에 바로 적용할 수 있다. 영역마다 업로드·AI 생성·비워두기를 혼합한다. 업로드 이미지는 기본적으로 규격을 꽉 채워 자르고, 위치·확대 또는 전체 보이기로 조정한다. 원본은 보존하며 조정 결과는 A4 미리보기와 인쇄에 동일하게 반영된다. 직접 업로드에는 Codex 로그인이 필요 없다.

직접 업로드와 참고 이미지는 파일당 최대 20MB이며, 한 요청의 총량도 20MB·최대 5파일이다. 인쇄에 쓰이는 이미지는 업로드 원본과 별도의 정규화 PNG 후보로 저장한다. 후보는 장변 최대 4096px까지 보존하며 PNG가 20MB를 넘으면 원본에서 3072px, 이어 2048px로 다시 변환해 가장 큰 허용 결과를 사용한다. 디자인·인쇄 화면의 `인쇄 이미지 N×Npx`는 이 후보의 크기를 뜻하며 업로드 원본의 픽셀 크기와 다를 수 있다. 기존 원본과 이미 생성한 후보는 변경하지 않는다.

이미지는 기존 ChatGPT 로그인으로 `codex exec`의 내장 이미지 생성 도구를 호출한다. 별도 API 키나 Gemini 연결은 사용하지 않는다. 생성은 계정의 사용 가능 기능과 한도를 따르며, 인증·생성 실패 시 오류를 표시한다. 이미지 결과는 실제 파일 형식·해상도를 검사한 뒤 앨범의 `assets/`에 보존한다.

AI 생성 요청에는 인쇄 실치수 기준 300PPI 원본 픽셀 목표(앞표지 1418×1418px, 뒷표지 1772×1394px, 라벨 1371×1371px, 스파인 256×1394px)를 포함한다. 스파인의 이론상 300PPI 가로 폭은 77px이지만 생성 PNG 검증의 각 축 최소 256px 조건에 맞춰 더 큰 폭을 요청한다. Codex CLI가 출력 크기를 강제하는 옵션을 제공하지 않으므로 목표 달성은 보장되지 않는다. 실제 앞표지 생성 시험은 1254×1254px, 약 265PPI로 기존과 같아 AI 생성 이미지의 원본 픽셀 향상은 확인되지 않았다. AI 생성 PNG는 임의 확대하거나 다시 압축하지 않고 그대로 보존한다. 디자인 후보와 인쇄 화면에는 인쇄 이미지의 실제 픽셀 및 현재 확대 배율을 반영한 추정 PPI를 표시하며, 300PPI 미만이면 경고하지만 인쇄를 막지는 않는다. 잘못된 픽셀 메타데이터는 0PPI로 취급한다. 축소·이동으로 이미지가 인쇄 영역을 다 채우지 못할 때도 여백 가능 경고를 표시하며, 축소만으로 PPI 목표를 달성한 것으로 계산하지 않는다. `이미지 전체 보기`는 흐린 채움 배경도 고려한 보수적 값이다. 픽셀 밀도와 AI가 그린 글자·세부묘사의 정확도는 별개이며, 의도적인 소프트포커스나 복고풍 압축 질감은 결함으로 간주하지 않는다.

AI 생성용 참고 이미지를 여러 장 선택할 때 각 사진에 임시 이름을 지정할 수 있다. 예를 들어 인물 사진을 `인물`, 배경 사진을 `배경`으로 지정하고 프롬프트에 `[인물]의 구도를 유지하고 [배경]의 색감을 적용해 줘`라고 쓰면, 앱이 첨부 순서와 이름을 함께 Codex에 전달한다. 이름을 비워두면 `이미지 1`처럼 순서 기반 이름을 사용한다. 이름은 영역별 초안 및 후보 생성 기록에 저장되며 실제 파일명은 바꾸지 않는다.

생성 중에는 진행 단계와 경과 시간을 표시한다. Codex가 정확한 완료율을 제공하지 않아 퍼센트나 남은 시간은 표시하지 않는다. 생성 중단 버튼으로 작업을 취소할 수 있다.

프롬프트 입력창에는 4000자 제한이 없다. 앱은 생성 요청 본문이 1MiB를 넘으면 잘라서 보내지 않고 오류를 표시한다. 긴 프롬프트도 Codex CLI 표준 입력으로 전달하지만, 모든 세부 지시가 이미지 결과에 반영되는 것은 생성 모델의 동작에 따라 달라진다.

제목·아티스트·트랙리스트 등 이미지에 넣고 싶은 글자는 생성 프롬프트에 적을 수 있다. AI가 만든 글자의 철자와 순서는 미리보기에서 확인해야 한다. 별도로 앱이 인쇄 단계에 정확한 앨범 메타데이터 글자를 올리는 기능도 선택할 수 있다. 뒷표지의 이 별도 기능은 앨범에 등록된 오디오 트랙명을 표시하며, 프롬프트에만 적은 세트리스트를 자동으로 옮기지 않는다. 이미지와 인쇄 오버레이에 같은 목록을 넣으면 중복될 수 있다. A4 미리보기와 인쇄는 같은 렌더러를 사용하며, 사진 배치·위치·확대 및 글자 설정을 저장한다. 디자인 화면에서 스튜디오 선택과 기존 HTML 디자인 중 인쇄할 소스를 명시적으로 선택할 수 있다.

스튜디오 상태는 `project.json`의 선택적 `studio` 필드에 저장되므로 기존 프로젝트를 그대로 열 수 있다. 후보 삭제는 이력에서 제거하는 동작이며 원본 이미지 파일은 보존한다. 사용 중인 후보·참고 이미지와 저장된 세트의 참조는 삭제로 끊어지지 않도록 보호한다.

선택 환경변수: `CDSTUDIO_CODEX_BIN`(실행 경로), `CDSTUDIO_IMAGE_CODEX_MODEL`(이미지 작업용 Codex 모델), `CDSTUDIO_IMAGE_TIMEOUT_MS`(기본 5분, 30초~15분). 이미지 작업은 사용자 Codex 설정을 무시하고 ChatGPT 로그인을 확인한다. 앱은 실제 PNG의 형식·디코딩을 검증하지만, CLI가 이미지 도구 실행 이벤트를 제공하지 않아 파일의 생성 경로 자체를 자동으로 증명하지는 못한다.

회귀 검증: `node tests/studio-view.mjs`, `node --test tests/image-generation.mjs`. 상태 API 테스트는 격리된 임시 라이브러리의 로컬 서버에만 `TEST_BASE_URL`과 `CDSTUDIO_TEST_LIBRARY`를 지정하여 `node tests/studio-api.mjs`로 실행한다.

전체 자동 회귀는 `npm run test:unit`, `npx tsc --noEmit`, `npm run lint`, `npm run build`로 실행한다. 실물 굽기는 공매체와 사용자 확인이 필요하므로 자동 테스트에서 수행하지 않는다. A4 인쇄는 브라우저 인쇄 설정에서 배율 100%와 여백 없음을 확인하고, 실제 출력 후 자로 치수를 검증한다.

## 음질 안내

원본이 스트리밍 음원(통상 ~160kbps Opus)이므로 CD 규격으로 변환해도 원본 이상의 음질은 될 수 없다.

## 기술 스택

Next.js (App Router) + React + TypeScript + Tailwind CSS. 단일 프로세스, 외부 도구(yt-dlp/ffmpeg/drutil/codex/claude)는 서버 라우트에서 실행.
